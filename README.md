# COMPSPHERE.ID — Hackathon Operations Platform

A production-oriented Phase 2 operations system for the PUFA CompSci Hackathon.
Replaces manual Devpost-to-event workflows with a centralized PostgreSQL-backed platform.

---

## Tech Stack

| Layer | Technology |
|---|---|
| Frontend | React 18 + Vite + TypeScript |
| Styling | Tailwind CSS v3 (custom design tokens) |
| State | TanStack Query v5 |
| Routing | React Router v6 |
| Backend | Express.js + TypeScript |
| Auth | better-auth + Google OAuth |
| Database | PostgreSQL (local) + Drizzle ORM |
| Real-time | Server-Sent Events (SSE) |
| File Storage | Local filesystem `/uploads/` (S3-compatible swap-ready) |
| QR Scanning | @zxing/browser |

## Setup

### 1. Install dependencies

```bash
npm install
```

### 2. Create PostgreSQL database

```bash
createdb compsphere
```

### 3. Configure environment variables

#### `apps/api/.env`
```env
DATABASE_URL=postgresql://localhost/compsphere
BETTER_AUTH_SECRET=<generate-with-openssl-rand-base64-32>
GOOGLE_CLIENT_ID=<your-google-oauth-client-id>
GOOGLE_CLIENT_SECRET=<your-google-oauth-client-secret>
BETTER_AUTH_URL=http://localhost:3001
CORS_ORIGIN=http://localhost:5173
PORT=3001
UPLOAD_DIR=./uploads
```

#### `apps/web/.env`
```env
VITE_API_URL=http://localhost:3001
```

### 4. Run database migrations

```bash
npm run db:migrate
```

This applies all Drizzle migrations to your local PostgreSQL database.

### 5. Seed initial data (optional)

```bash
npm run db:seed
```

Populates 100 qualified teams, proposals, Battle Royale slots, and system config parameters.

### 6. Start development servers

```bash
# Terminal 1 — API server
npm run dev --workspace=apps/api

# Terminal 2 — Web frontend
npm run dev --workspace=apps/web
```

Frontend: [http://localhost:5173](http://localhost:5173)  
API: [http://localhost:3001](http://localhost:3001)

## Google OAuth Setup

1. Go to [Google Cloud Console](https://console.cloud.google.com/) → **APIs & Services** → **Credentials**
2. Create an **OAuth 2.0 Client ID** (Application type: Web application)
3. Add authorized redirect URI:
   ```
   http://localhost:3001/api/auth/callback/google
   ```
4. Copy **Client ID** and **Client Secret** into `apps/api/.env`

## Migration Workflow (Devpost CSV → Platform)

1. Export teams from Devpost as CSV
2. Log in as Admin → navigate to **Migration** page
3. Upload the CSV — preview and validate rows
4. Click **Commit Migration** — system generates activation tokens for Top 30
5. Export tokens CSV and distribute to team leaders

**Expected CSV columns:**
```
rank, team_name, team_code, category, institution, country
```

## Role System

| Role | Access |
|---|---|
| `USER` | New user — must complete onboarding |
| `PARTICIPANT` | Team leader/member — Participant console |
| `ADMIN` | Operations staff — Admin console |
| `JUDGE` | Evaluator — Judge console |

Roles are assigned at onboarding using **activation tokens**. Admins and Judges use special one-time role tokens generated by the admin.

---

## Key Business Rules

- **Top 30 SLA:** Teams have 48 hours to confirm after being notified. Expired slots cascade to the Waitlist automatically.
- **Payment:** National/Mix teams pay Rp120,000. International teams submit commitment letters (amount = 0).
- **Battle Royale:** Waitlist slots are claimed atomically using `SELECT FOR UPDATE SKIP LOCKED` — no double-booking under concurrent load.
- **Submission Lock:** Deliverables are locked after the deadline; no modifications after lock.
- **QR Attendance:** Each QR token is single-use per attendance type (Day 1, Day 2, Ceremony).
